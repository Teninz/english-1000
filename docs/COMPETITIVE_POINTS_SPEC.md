# Соревновательные баллы

Статус: согласованная основа для будущей реализации. Учебный прогресс остаётся локальным. В сеть передаётся только текущее количество баллов пользователя; идентификатор пользователя, неделя, поколение счёта и время публикации являются служебными полями протокола.

## Цель

Рейтинг должен поощрять регулярное запоминание слов и не давать преимуществ за многократные ответы, досрочные повторы, подсказки или намеренные ошибки. Основной рейтинг — недельный среди добавленных друзей.

## Начисление

| Событие | Баллы | Условие |
| --- | ---: | --- |
| Слово впервые поднялось на новую интервальную ячейку | +5 | Первый самостоятельный правильный ответ в плановый день |
| Слово впервые достигло статуса «знаю» (ячейка 3) | +10 | Дополнительно к +5 за новую ячейку |
| Слово впервые достигло статуса «закреплено» (ячейка 6) | +20 | Дополнительно к +5 за новую ячейку |
| 10 зачётных продвижений разных слов за день | +10 | Один раз в день |
| Учебная активность в 4 разных дня недели | +25 | Один раз за неделю |
| Тематический блиц впервые пройден | +50 | Один раз на маршрут |
| Первое подтверждение условно известного слова из стартовой проверки | +5 | Самостоятельный ответ в назначенный день |

Не дают баллов:

- просмотр новой карточки без правильной проверки;
- досрочный повтор до плановой даты;
- второй и последующие ответы по слову в тот же день;
- ответ с подсказкой или принятый как близкий вариант;
- кнопка «Уже знаю» и сама стартовая проверка;
- повторное прохождение уже сданного тематического блица;
- ошибочный ответ.

Ошибка не отнимает баллы. Для каждого слова хранится максимальная уже оплаченная ячейка `maxScoredBox`. Если пользователь намеренно ошибётся, понизит слово и снова поднимет его до прежней ячейки, новых баллов не будет.

Дневной предел рейтинговых начислений — 200 баллов. Учиться после достижения предела можно без ограничений. Интерфейс сообщает, что дневной предел рейтинга достигнут.

## Недельный рейтинг

Неделя определяется сервером. В таблице друзей показываются:

- псевдоним;
- баллы текущей недели;
- время последнего ручного обновления.

Сервер не получает список слов, ответы, ошибки, интервалы, серии или учебную статистику. Учебная часть запроса содержит только абсолютное значение `points`. Сервер заменяет сохранённое значение, а не прибавляет присланную разницу.

Минимальный запрос публикации:

```json
{
  "user_id": "служебный идентификатор",
  "device_id": "активное устройство рейтинга",
  "week_id": "неделя по серверному календарю",
  "score_epoch": "поколение счёта",
  "points": 385
}
```

`user_id`, `device_id`, `week_id` и `score_epoch` нужны для адресации и защиты от устаревших копий. Единственное передаваемое значение учебного прогресса — `points`.

## Ручное обновление

Кнопка «Обновить» выполняет одну операцию:

1. публикует локальную сумму пользователя;
2. получает последние опубликованные суммы друзей;
3. сохраняет таблицу друзей в локальный кэш.

Автоматической синхронизации при запуске, сворачивании или фоновой работе нет. Сервер принимает не более двух успешных операций пользователя за календарные сутки по серверному времени. Неудачный сетевой запрос не расходует попытку. Интерфейс показывает число оставшихся обновлений и время последнего успешного обновления.

Для первой версии один аккаунт имеет одно активное рейтинговое устройство. Это исключает сложение двух независимых локальных прогрессов. Перенос на другой телефон выполняется через экспорт/импорт прогресса и явную смену активного устройства.

## Локальное хранение

Баллы входят в ту же проверяемую локальную модель, что и учебный прогресс, чтобы изменение ячейки и начисление сохранялись одной операцией. Предлагаемая структура:

```text
score:
  version
  epoch
  activeWeek
    weekId
    points
    dailyPoints
    qualifyingWordsByDay
    activeDays
    bonuses
    events
  lifetime
    points
    byScope
  milestones
    main[wordKey].maxScoredBox
    thematic[routeId][wordKey].maxScoredBox
    verifiedKnown
    passedExams
  sync
    lastSuccessAt
    lastPublishedPoints
    pendingReset
```

В `events` хранится только журнал текущей недели с уникальными идентификаторами начислений. Старые недели сворачиваются в локальные итоги по областям. Область события — `main` или `thematic:<routeId>`. Уникальный идентификатор, например `main:word|v:box:3`, делает начисление идемпотентным.

На Android локальный счёт и поколение дополнительно подписываются ключом из Android Keystore. Это защищает от простого редактирования файлов, но не гарантирует абсолютную защиту на взломанном устройстве. При условии передачи только итоговой суммы полностью проверить честность начислений на сервере невозможно; система рассчитана на дружеское соревнование.

## Сброс прогресса

Баллы не переживают прогресс, за который они начислены.

- Полный сброс удаляет все локальные начисления, недельные и общие баллы, создаёт новую `score_epoch` и ставит `pendingReset`.
- Сброс основного курса удаляет события и итоги области `main`, затем пересчитывает дневные и недельные бонусы.
- Сброс тематического маршрута удаляет область `thematic:<routeId>`, отметку его блица и связанные бонусы, затем пересчитывает итог.
- Диалог подтверждения прямо сообщает: «Будут удалены учебный прогресс и заработанные за него баллы».

Локальное значение меняется сразу. Серверный рейтинг обновляется только после следующего ручного нажатия «Обновить» и расходует одну суточную попытку. До публикации интерфейс показывает «обнуление ещё не опубликовано».

Сервер принимает уменьшение баллов только вместе с новой `score_epoch` или разрешённым частичным сбросом. После подтверждённого сброса запрос со старой эпохой отклоняется, поэтому устаревшая резервная копия не возвращает удалённые баллы.

## Серверная часть

Отдельный постоянно работающий процесс не нужен. Достаточно управляемого сервиса наподобие Supabase:

- авторизация и восстановление аккаунта;
- профили и коды добавления друзей;
- закрытые связи друзей;
- таблица недельных баллов;
- серверная функция публикации и получения рейтинга;
- ограничение двух обновлений в сутки;
- правила доступа, позволяющие видеть баллы только подтверждённым друзьям.

Прямое соединение телефонов не подходит для основной схемы: оба устройства должны быть одновременно онлайн, мобильные системы останавливают фоновые процессы, NAT мешает входящим соединениям, а WebRTC всё равно требует сервера сигнализации.

## Этапы реализации

1. Добавить локальную модель баллов, расчёт начислений, лимит и сбросы без сети.
2. Добавить экран «Рейтинг» с тестовыми локальными участниками и проверить понятность шкалы.
3. Подключить профили, друзей и серверную функцию ручного обновления.
4. Добавить привязку активного устройства, `score_epoch`, защиту от старых копий и Android Keystore.
5. Провести закрытый тест и скорректировать шкалу по реальному темпу обучения.
